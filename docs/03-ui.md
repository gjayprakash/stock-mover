# UI / UX (one screen does 90% of the demo)

Design goal: **approve the whole list in 10 minutes.** It should feel like an inbox, not a dashboard.
Look: warm cream background, saffron/orange accent, deep maroon for emphasis, serif headings
(the brief's own palette), lots of white space, big readable numbers.

## Screen 1 — Today's moves (home)
**Header strip**
- "Stock Mover" · As of 31 Oct 2026 · Last run 06:00 today · Next run 06:00 tomorrow (proves it runs on its own)
- 4 stat tiles: Moves to approve · Units moving · ₹ sales protected · Rule check "0 violations" (green)

**Morning brief card (AI, MeshAPI)**: 4–5 lines. "3 stores will run out of Kurta Sets before Diwali…"

**Tabs with counts**: All · Warehouse → Store · Store → Store · Ageing · Pull back
**Filters**: store, city, category. **Sort**: priority (default).

**Move rows, grouped by destination store** (group header: store, tier, capacity used bar, "Approve all N")
Each row, left to right:
- Style name + size chip (e.g. "Teal Cotton Silk Kurta Set · XL")
- `WH-KOL → LKO-03` with an arrow, qty big and bold
- The one-line reason
- Cover chip: `7d → 37d` (red → green)
- Arrives `4 Nov`
- Confidence dot (own / blended / peer data)
- ✓ Approve / ✕ Reject

**Row expand (click)**: 12-week mini chart of sales vs stock with out-of-stock weeks shaded,
before/after numbers for both ends, and the five rule checks each with a green tick.
This is what convinces a judge the number is right.

**Speed features (cheap, high impact)**
- Keyboard: J/K move, A approve, R reject, Shift+A approve group
- Sticky footer: "42 of 118 approved" progress + **Export approved (CSV)**
- "Approve all high-confidence" button

## Screen 2 — Ask Stock Mover (side drawer, AI)
Chat grounded in moves.json. Suggested chips: "Why is LKO-01 not giving stock?",
"Which stores are most at risk this week?", "What did you find in the new store?"

## Screen 3 — Found problems (only if time, 20 min max)
Cards for each item in the hidden-problem checklist with the count we found
("7 stockouts hiding real demand"). Great for the judges' "did you find them" check.

## Do not build
Login, settings, charts page, store map, dark mode, mobile.

## Stack for UI
Next.js App Router + Tailwind + shadcn/ui (Table, Tabs, Badge, Sheet, Button). Recharts for the mini chart.
Build against `packages/contract/moves.sample.json` from minute one; swap to real `moves.json` when the engine lands.
